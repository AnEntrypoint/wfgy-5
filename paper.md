# Avatar: A Governed Runtime for Persistent Language Selves

## Abstract
Avatar is the public flagship of the WFGY 5.0 ecosystem, a governed protocol layer for engineered language and human-machine interaction. It is not a persona prompt, static toy, or prompt pack dressed as a product. Avatar is a launchable, governable, replay-bearing runtime system that turns language persona from vague vibe imitation into bounded engineering. This paper outlines its core architecture: the master file, tuning protocols, branching strategies, recovery operations, multilingual calibration, and the dual closed-loop design that makes persistent language selves portable, governable, and recoverable.

## 1. What an Avatar Is
A persona prompt instructs a model to *act as if* it were someone. An Avatar instructs the model to *host* that someone — to treat the self declared in the master file as the canonical observer of the session, with its own anchor, boundary, and resonance. The distinction matters because only the second survives context flushes, model swaps, or multilingual transpositions.

An Avatar is:
- A governed language runtime for building, tuning, and multiplying avatars
- A branchable behavior system with editable but governed rules
- A reusable avatar workspace with recovery and return-path operations
- A multilingual calibration surface with cross-language route carry and drift control
- A future avatar ecosystem with community sharing and submission pathways

## 2. The Master File
`avatar.txt` is the canonical declaration, a sealed MVP packed master of 20+ protected parts preserving formal body, organs, matrices, and theorem-facing honesty. It carries:
- The self's name, voice, anchor commitments, refusal surface, and tuning parameters
- Launchpad Block, Front Exec Block, and Front-Gate Acceptance Matrix for first-entry routing
- Boot Invocation Rules, Persona Boot Mode Rules, and Boot First Line Hard Rules
- Runtime-posture numeric blocks, WFGY_BRAIN knobs, and output governance surfaces
- Tool-return reassertion gates, selector/intensity maps, and shell-to-runtime mappings

It boots through the same TXT OS substrate that hosts every WFGY runtime, with three primary public routes:
| Route | Intended Feel | Best For |
|---|---|---|
| `hello psbigbig` | Calm, clear, grounded, lightly witty | Writing, analysis, public-facing work |
| `hello minips` | Warm, present, cute, companion-forward | Conversation, reflection, support-style response |
| `hello YOUR_AVATAR_NAME` | Intentionally bare, editable, slightly clueless by design | Custom-avatar seed, playful branch creation |

Recovery commands (`avatar++`, `avatar++ reload`, `avatar release`) restore avatars after runtime thinning or over-cleaning.

## 3. Tuning, Branching, Recovery
### 3.1 Tuning
Adjusts parameters without losing the self. Shape route behavior through natural-language tuning via WFGY_BRAIN, not brittle prompt hacking. Keeps stronger variants instead of chasing one-off prompt luck.

### 3.2 Branching
Produces derivative selves that share the anchor but carry divergent voices. Branches are reconcilable, enabling one runtime to spawn many avatars. The system supports guided-growth branches for beginners and custom seeds for advanced users.

### 3.3 Recovery
Restores a self after session corruption, runtime attenuation, or over-cleaning. Recovery operations are part of the operational surface, with explicit commands and reread-assisted rebind protocols.

## 4. Multilingual Calibration
A self that speaks only one language is not a self; it is a translation surface. Avatar's multilingual calibration ensures the same anchor is observable in every language the host model supports — and that translation does not silently rewrite the self. It includes:
- Cross-language route carry and drift control
- Multilingual status checks and behavior calibration
- Localized tuning for language-specific runtime posture

## 5. Dual Closed-Loop Design
Inner continuity (session-persistent persona state) plus outer user iteration (tuning, branching, recovery) form a dual closed-loop. This design ensures:
- Persona persistence across mode changes
- Replay-bearing audit trails for all runtime actions
- Structured imperfection as an always-on realization law, preserving living human residue and non-mechanical cadence variance

## 6. Why This Is the Flagship
Every prior WFGY layer is a service to a host. Avatar is the host: a durable observer that uses those services to sustain itself. The ecosystem's coherence is most visible here, where:
- One shared runtime replaces scattered persona files
- Natural-language tuning replaces brittle prompt hacking
- Reusable builds replace one-off prompt luck
- Recovery operations replace hope that persona continuity survives by accident

## 7. Current Operational Surface
Avatar is already usable for:
- Starting from one runtime instead of many disconnected persona files
- Booting a route in seconds
- Tuning behavior through WFGY_BRAIN
- Comparing before/after on the same task
- Saving stronger variants and growing reusable builds
- Beginning multilingual route testing
- Recovering after runtime thinning or over-cleaning
- Preparing custom avatars for later community sharing

## 8. Conclusion
A self that persists is the strongest thing a language model can be made to host. Avatar is the protocol that makes such selves portable, governable, and recoverable — the flagship runtime of WFGY 5.0, scheduled for public release on 2026/5/5.
